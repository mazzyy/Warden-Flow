Nothing is trusted, including the fix
The verifier runs after the merge and reads the estate itself. A single prompt asked to "fix this" declares victory in the same breath as the fix. Here, proposing and confirming are different nodes with different tools — and the one that proposes cannot be the one that approves.
The revert loop
verifier → request_revert → new PR → human review → sync → verifier. Rolling back a change that did not help is cheap; leaving a broken service in production while you deliberate is not. The loop closes only when a human merges and the verifier independently confirms recovery.
Budgets, per node
triage 20k tok · 6 calls · diagnostician 120k · 25 · remediator 120k · 20 · verifier 40k · 15. Checked before every dispatch, so a runaway loop is stopped by the ledger rather than noticed on an invoice.
