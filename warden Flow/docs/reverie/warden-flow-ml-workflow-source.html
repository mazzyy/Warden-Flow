Warden Flow — two governed LLM workflows, one spine

Every node is a separate prompt that returns a typed object — a Pydantic schema the runtime enforces — and hands that structure to the next node. No single prompt makes every decision. The fleet's only write primitive is a pull request; a human decides whether it lands.

the only node that can send the workflow backwards — see the two outcomes below
↳ outcome A · recovered → close
Status and metrics match what the incident described — replicas_ready 3/3, error_rate < 0.05. The verifier closes the incident: status resolved, closed_at stamped, the full trace retained in the audit store. The workflow ends.
↳ outcome B · did not recover → revert loop
The verifier calls request_revert(pr_number, reason), which opens a second pull request reverting the merged change. It cannot roll the cluster back itself — the revert is a PR like any other. That PR re-enters node 4, human review, and the loop runs again from there.
Revert loop
verifier → request_revert → new pull request → human review (node 4) → GitOps sync → verifier. The loop closes only when a human merges and the verifier independently confirms recovery. At no point does any agent write to the cluster, merge a pull request, or hold a credential that would let it.
Governance spine — enforced on every node in both workflows manifests/agents/*.yaml · manifests/delivery/*.yaml
Typed output
Every node declares a Pydantic schema. The runtime enforces it; an unparseable response is a failed node and stops the workflow rather than passing nothing downstream.
Scoped tools
Tools come from the manifest, not the code. A node can only call what it was granted — an ungranted call is denied by the proxy and recorded as a denial.
Budget ceiling
Per-run token and tool-call caps, checked before every dispatch. A runaway loop is stopped by the ledger, not by hope.
Blast radius
Maximum files and changed lines per patch. Exceeding it is refused at the write path, so an over-eager fix cannot be produced at all.
Audit trail
Every tool call — allowed or denied — is written with agent, decision, reason, latency and token cost, per incident.
