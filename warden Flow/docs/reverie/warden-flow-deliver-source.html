Why five prompts, not one
A single prompt asked to "write my DevOps" makes every decision at once, cites nothing, and cannot be inspected mid-flight. Each node here has one job, a capped budget, and an output another node must be able to read — so a bad answer is caught at the handoff, not in production.
The governance spine
Scoped tools from a YAML manifest — an ungranted call is denied and recorded. Budget ceiling per run, checked before every dispatch. Blast radius caps files and lines. Audit trail on every call, allowed or denied.
The same spine runs OPERATE
Pointed the other way: a production alert goes in — triage → diagnose → remediate → human review → verify — and a GitOps fix comes out as a pull request. If the fix did not work, the verifier opens a revert PR and the loop runs again.
LLM node — a prompt + an enforced output schema
Human input — required; nothing proceeds without it
Deterministic — no model involved
Every node is policy-scoped, budget-capped and audited — tools come from a YAML manifest, not the code.
